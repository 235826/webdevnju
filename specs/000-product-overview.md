# 000：足球赛事平台总体范围

> 状态：已验收
>
> 关联事项：Web 开发技术课程大作业

## 目标

用户可以围绕足球赛事完成浏览、预测、收藏、讨论和结果查看，管理员可以维护赛事数据并录入比赛结果。

## 用户故事

作为足球赛事平台用户，我希望在一个平台中查看赛事、球队、赛程、榜单并参与比分预测和讨论，以便获得完整的赛前到赛后互动体验。

## 范围

- 项目面向通用足球赛事，不绑定世界杯或苏超单一主题。
- 支持 Competition → Stage → Match 的统一赛事结构。
- Stage 至少支持 `GROUP`、`LEAGUE`、`KNOCKOUT` 三类赛制阶段。
- 所有预测、收藏和评论均关联统一的 Match。
- 支持真实注册登录、管理员种子账号、移动端适配、持久化数据和一条命令 Docker 交付。

## 非目标

- 不实现自动赛事编排。
- 不根据小组积分自动生成淘汰赛对阵。
- 不为小组赛、联赛和淘汰赛分别建立独立比赛模型。
- 不处理比赛延期、取消或开赛时间变更。

## 业务规则

- **BR-01**：赛事数据必须通过统一 Competition → Stage → Match 结构表达。
- **BR-02**：比赛状态只包括未开始、进行中、已结束。
- **BR-03**：比赛是否已经开始必须由服务端根据比赛开始时间判断。
- **BR-04**：数据必须持久化，重启服务后核心业务数据不得丢失。
- **BR-05**：前后端通过 RESTful `/api/*` 接口通信，HTTP 边界以 `contracts/openapi.yaml` 为准。

## Contract 影响

- 结论：无。
- 理由或影响摘要：本 Spec 只定义总体范围，具体 HTTP 行为由后续功能 Spec 和 OpenAPI 分别约束。
- OpenAPI operation：无。
- 迁移 / 废弃安排：不适用。

## 验收标准

- **AC-01**：给定项目规格集，当阅读所有 P0 Spec 时，可以明确识别用户浏览赛事、登录、预测和管理员录入结果的核心闭环。
- **AC-02**：给定任一比赛，当系统展示、预测、收藏或评论该比赛时，均使用统一 Match 概念作为业务对象。
- **AC-03**：给定任一赛事阶段，当阶段类型为 `GROUP`、`LEAGUE` 或 `KNOCKOUT` 时，系统可以按对应赛制展示该阶段。
- **AC-04**：给定服务重启，当用户重新访问平台时，已创建的核心业务数据仍可通过 API 查询。
