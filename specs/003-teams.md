# 003：球队信息

> 状态：草案
>
> 关联事项：Web 开发技术课程大作业

## 目标

用户可以查看球队基础信息，并在比赛相关页面识别参赛球队。

## 用户故事

作为赛事观众，我希望查看球队资料，以便理解比赛双方和赛事参与者。

## 范围

- 球队列表。
- 球队详情。
- 比赛详情中的主客队或对阵双方展示。
- 球队与外部资料来源的关联标识。

## 非目标

- 球员级资料。
- 球队阵容、伤停和转会信息。
- 手动同步外部 API 的完整数据管理流程。

## 业务规则

- **BR-01**：每支球队应具有可展示名称。
- **BR-02**：比赛必须引用统一的球队数据，不在比赛中重复维护独立球队资料。
- **BR-03**：球队详情可以展示本地资料和外部 API 补充资料。
- **BR-04**：外部资料不可用时，球队基础资料仍应可展示。

## Contract 影响

- 结论：新增。
- 理由或影响摘要：需要新增球队读取接口，并供比赛、榜单和外部资料集成引用。
- OpenAPI operation：`GET /api/teams`、`GET /api/teams/{teamId}`。
- 迁移 / 废弃安排：不适用。

## 验收标准

- **AC-01**：给定存在球队数据，当用户打开球队列表时，则可以看到球队名称和基础信息。
- **AC-02**：给定球队详情请求成功，当用户进入球队详情页时，则页面展示该球队的本地资料。
- **AC-03**：给定比赛关联双方球队，当用户查看比赛详情时，则可以识别比赛双方。
- **AC-04**：给定外部球队资料不可用，当用户查看球队详情时，则页面保留本地资料并显示降级提示。
- **AC-05**：给定球队列表为空，当用户打开球队列表时，则页面显示明确空状态。
