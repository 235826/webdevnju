# 012：Docker 交付

> 状态：已验收
>
> 关联事项：Web 开发技术课程大作业

## 目标

项目可以在 linux/amd64 环境通过一条命令启动前端、后端和持久化关系型数据库文件。

## 用户故事

作为课程验收人员，我希望用一条命令启动完整系统，以便在标准环境中复现实验结果。

## 范围

- 前端容器化。
- 后端容器化。
- SQLite 关系型数据库文件通过 Docker volume 持久化。
- 一条命令启动完整服务。
- 初始化管理员种子账号。
- 提供必要环境变量说明。

## 非目标

- 生产级高可用部署。
- 云平台自动部署。
- 多节点扩缩容。
- 线上证书和域名配置。

## 业务规则

- **BR-01**：交付物必须可在 linux/amd64 环境运行。
- **BR-02**：一条命令启动后，前端、后端和 SQLite 数据库文件应能协同工作。
- **BR-03**：数据库数据必须持久化到容器生命周期外的可保留存储中。
- **BR-04**：启动后必须存在可登录的管理员种子账号。
- **BR-05**：交付物不得要求提交 `.env`、凭据、生成数据库或构建产物到版本控制。

## Contract 影响

- 结论：无。
- 理由或影响摘要：本 Spec 约束交付和运行方式，不改变 HTTP 请求或响应。
- OpenAPI operation：无。
- 迁移 / 废弃安排：不适用。

## 验收标准

- **AC-01**：给定干净的 linux/amd64 环境，当执行文档声明的一条启动命令时，则前端、后端和 SQLite 数据库文件均启动或初始化成功。
- **AC-02**：给定服务启动完成，当访问前端页面时，则页面可以通过后端 API 获取数据。
- **AC-03**：给定服务启动完成，当使用管理员种子账号登录时，则系统识别为管理员。
- **AC-04**：给定写入业务数据并重启容器，当再次查询时，则数据仍然存在。
- **AC-05**：给定仓库提交内容，当检查版本控制文件时，则不包含 `.env`、凭据、生成数据库或构建产物。
